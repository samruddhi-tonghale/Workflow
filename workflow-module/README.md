# Workflow Module

A single generic workflow with a TypeScript frontend, Python backend, and SQLite persistence.

## Run locally

Requires Python 3.10+ and Node.js/npm to rebuild the frontend.

```powershell
cd D:\WorkflowModule
python backend\server.py
```

Open http://127.0.0.1:8000. The saved workflow lives in the project-root `workflow.db`.

To rebuild the TypeScript frontend after changing `frontend/app.ts`:

```powershell
npm install
npm run build
```

## APIs used by the frontend

- `GET /api/health` — service status and integration availability.
- `GET /api/workflows` — fetch the single workflow.
- `GET /api/workflows/{id}` — load its configuration and diagram.
- `PUT /api/workflows/{id}` — save diagram and settings.
- `POST /api/workflows/{id}/test` — preview-only route trace; no model is called.
- `GET /api/registry/orchestrators` and `GET /api/experts` — empty integration placeholders.
- `POST /api/workflows` — reserved; returns a conflict when the single workflow already exists.
- `DELETE /api/workflows/{id}` — soft-delete. If deleted, a generic workflow is seeded next time the backend starts.

Orchestrator, Experts, and real LLM execution are not connected yet. The app serves the frontend and API from the same local server.
